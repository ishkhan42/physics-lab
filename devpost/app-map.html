01 · Purpose

A mechanics workbench, not a general physics simulator

Physics Lab turns a described mechanics situation into validated scene data, prepares it with the native MuJoCo engine, and renders the actual state for inspection. The AI chooses supported data blocks; trusted code validates and compiles them. A scene opens paused: pressing Run is a separate user action.

  • Browser workbench React manages the request and scene; Three.js draws the experiment, with read-only object cards and sampled motion charts.
  • Node service and isolated worker The local API brokers the selected external model. A bounded Docker worker gets lab tools, not shell, host files, or network access.
  • Trusted mechanics path Shared schemas admit mechanics data; the MuJoCo builder, runtime and observations handle the physics rather than model-written code.

02 · One real action

Describe → check → inspect

  1. Describe

    src/App.tsx sends the description to the configured /api/lab endpoint. server/providers.ts brokers inference with the selected model provider; the browser does not hold provider credentials. Hosted subscription-demo mode uses server/demo.ts for the authorized model window and server/subscription-auth.ts for private credential renewal.

  2. Assemble and check

    The isolated agent uses bounded lab tools. Normal ready handoffs require native checks and separate-context review by the selected model. A rare checked-but-unsettled proposal needs explicit user acceptance before saving. Checks run a native 0.5-second warm-up, not the whole future experiment.

  3. Save paused, then run

    The API saves an immutable setup in private SQLite locally or Firestore when hosted. The browser prepares the native runtime and shows a paused preview, measured cards and charts. Run starts playback; inspection reads solver state.

Storage and services: inference uses the configured provider through the trusted broker. Hosted runs pass through server/sandbox.ts and the authenticated private server/worker-gateway.ts to fresh network-denied Docker workers; image inspection uses server/renderer-client.ts and a separate keyless, IAM-protected server/render-gateway.ts through bounded broker RPC. Neither service is a browser endpoint. Scene documents use local private SQLite or hosted Firestore and expire 24 hours after the latest Run/Resume. Browser recents contain link metadata only. Credentials and provider settings are not saved with scenes.

Prepared examples: Five visual studies cover double pendulums starting 5° apart, an impacting spring net, three-body choreography, contact losses on a frictionless loop, and a curved domino cascade. Preview images are captured from actual native simulations. Open setup creates a new paused saved copy without inference or provider credentials; Start from prompt fills an editable draft without saving or sending it. Definitions remain available after old links expire, and existing saved scenes are unchanged. Neither path replaces freeform prompting or acts as a fallback for a failed build. The visual reference grid is off by default; hiding it never removes ground or changes physics.

03 · Reference route

Three stops through the implementation

  1. Follow the submitted description

    Start at src/App.tsx — handleSubmit. It validates the request and posts to /api/lab. Follow server/index.ts — handleRequest to the route, then server/harness.ts — runLab and server/providers.ts — providerKey/streamLabModel to see the brokered model call and bounded worker handoff.

  2. Trace admission into native evidence

    In server/harness-worker.ts, search for check_experiment and finish_experiment. They use src/physics/mjcf.ts — compileMjcf, src/physics/native-check.ts — advanceNativeCheckTo, and an independent reviewer. shared/harness.ts defines limits: 16 model requests, 24 lab-tool calls and 240 seconds per run, with two model requests reserved for review.

  3. Watch the paused preview become observable

    Back in src/App.tsx, search saveSceneDocument and preparePreview. src/SimulationCanvas.tsx prepares createRuntime and gates playback in toggleRunning. src/ObjectCards.tsx and src/TelemetryPanel.tsx display native observations and sampled motion. The preview begins paused; rendering or inspection does not itself run inference.

    For loaded connectors, follow src/physics/types.ts — RenderItem.tendon, src/physics/mujoco.ts — native routes and signed branch forces, and src/tendon-visuals.ts — TendonVisual. The shared viewer and inspection use the same geometry. shared/scene.ts — TendonSchema exposes optional presentation-only controls; coils and slack bows do not add material or collision physics.

05 · Numerical limits

A valid model is not proof of the requested physics

The calibrated contact layer targets restitution coefficients 0, 0.5 and 1; tests/contacts.test.ts checks selected sphere-plane impacts to absolute tolerances 0.015, 0.04 and 0.01 respectively. These finite-step results are not a universal accuracy guarantee.

Native readiness covers initialization and a 0.5-second warm-up, not later scheduled events or long-term behavior. The independent reviewer is a model call, not human validation.

06 · Reopen the workbench

Build and start locally

Use Node 24.12 or later in the Node 24 line, npm, Docker, and access to a running Docker daemon. The project’s documented install is npm ci --ignore-scripts; then build the app and start it:

npm ci --ignore-scripts
npm run build
npm start

npm start runs the prestart hook to build/cache the sandbox image and serves the built app at http://127.0.0.1:3001. First sandbox setup needs registry access to fetch the Node base image and pinned packages. The worker container itself has no network access.

For an authorized provider, use the secret-free .env.example as the server-side template; keep real credentials in a private file outside this public checkout. The map contains no credentials or private data. See README.md for configuration details.
